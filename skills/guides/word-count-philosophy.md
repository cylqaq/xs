# 字数哲学：故事合理性优先

> **核心原则**：字数是参考指标，不是硬性目标。故事合理性、章节编排的恰当性优先于字数达标。

## 一、字数限制的本质

### 1.1 硬性条件（必须满足）
- **最低字数**：1600 汉字（`minWordsHardFail`）
- **目的**：确保章节有足够的叙事内容，避免碎片化
- **违反后果**：`forge draft check` 会标记为 `fail`，必须通过 `@chapter-expander` 扩写

### 1.2 软性目标（参考而非强制）
- **目标范围**：2000–4500 汉字（`minWordsPerChapter` – `maxWordsPerChapter`）
- **目的**：提供合理的章节长度参考，避免过长或过短
- **违反后果**：`forge draft check` 会标记为 `warn` 或 `long`，但不会阻止 handoff

## 二、故事合理性优先原则

### 2.1 章节结束的自然时机
当以下任一条件满足时，本章应该结束：
1. **叙事单元完成**：本章的核心冲突/转折已经展开并得到解决
2. **情感弧线完整**：本章的情感高潮和回落已经完成
3. **悬念承上启下**：已经为下一章埋下足够的悬念或钩子
4. **beats 覆盖完成**：本章的 beats 要求已经全部覆盖

### 2.2 禁止的凑字行为
1. **章末堆字**：在章末添加无叙事功能的"第N日尽"式摘要
2. **重复收束**：多次重复相似的章末收束语句
3. **无意义扩展**：为达到字数而添加对情节无推动的对话或描写
4. **登记册语言**：将框架术语（如"埋设伏笔"、"弧光摘要"）写入正文

## 三、字数检查的正确使用

### 3.1 `forge draft check` 的解读
- **tier=ok**：字数在目标范围内，无需调整
- **tier=warn**：字数低于目标但高于硬下限，可选择性扩写
- **tier=long**：字数超过软上限，可选择性精简
- **tier=fail**：字数低于硬下限，必须扩写

### 3.2 扩写原则
当需要扩写时，遵循以下优先级：
1. **beats 中段扩展**：增加感官描写、对话细节、动作描写
2. **情感深度挖掘**：深入角色的内心世界，增加情感层次
3. **环境氛围渲染**：增加场景的细节描写，增强沉浸感
4. **冲突张力提升**：增加冲突的复杂性和紧张感

**禁止**：章末添加说明文、重复摘要、无功能对话

## 四、配置建议

### 4.1 新书默认配置
```json
{
  "minWordsPerChapter": 2000,
  "minWordsHardFail": 1600,
  "maxWordsPerChapter": 4500
}
```

### 4.2 按体裁调整
- **短篇/中篇**：可适当降低 `minWordsPerChapter` 到 1500
- **长篇连载**：保持默认配置，确保章节有足够内容
- **实验性作品**：可放宽 `maxWordsPerChapter` 到 6000

## 六、执行流程

1. **写章时**：专注于故事合理性，不要考虑字数
2. **章完成后**：运行 `forge draft check` 查看字数评估
3. **如果 tier=warn**：评估是否需要扩写，优先考虑叙事完整性
4. **如果 tier=fail**：必须扩写，但遵循扩写原则
5. **如果 tier=long**：评估是否需要精简，优先考虑阅读体验

**记住**：宁可短而干净，不可长而凑字。
